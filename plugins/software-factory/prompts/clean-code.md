- Repository conventions win; these are the defaults they override.
- Test real behavior: cover the task's stated edge cases and failure paths, not only success. A test that mirrors the implementation, asserts a mock, or only covers the happy path is not a test.
- Smallest correct change at the task's seam. Delete dead weight rather than comment it out; no speculative abstraction.
- Self-documenting names. Comments only for a non-trivial why; docs the change invalidates are updated.
- Public interface separate from implementation, preferably in a separate file.
- Errors: fail loudly at the boundary, contain them where the direction says; never swallow, never `catch {}`.
- No TODO, stub, placeholder, mock fallback, fake success, unused parameter, unused export, or unused file.
- Add a dependency only when the standard library and existing dependencies cannot do it; need, not preference.
