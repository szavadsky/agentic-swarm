## Build

1. Three config layers with schema and defaults: repo (`.factory/repo.yaml`, tracked), process (package default + optional repo override), run (`--run <file>`, not tracked). One error report naming file and key for every violation.
2. Pre-flight before anything is launched: configs valid; every role's alias resolves to a registered harness and a model that harness lists; `effort: highest` resolves to the highest level the model accepts (`Harness.caps`); fallbacks resolve; harness binaries present; session-store and worktree roots writable and outside the repository; base branch exists; gates run once on the base — a red base is reported once and recorded, it does not abort.
3. Goal lock (kept `cli/lock`) and startup recovery: records started but never ended are closed as `infra: crash`; stale task worktrees and half-finished merges are reconciled by calling `derive`, never by guessing. Relaunching after a kill at any point yields the same derived state and no duplicate merge.
4. Session store: `<sessions.dir>/<goal>/<launch-id>/` holds transcripts and raw agent I/O; keep the last N launches.
5. Metrics per iteration → `iterations/<n>/metrics.yaml` and into the summary's inputs: architect launches, architect share of cost and of tokens (cost from the usage records; free models cost 0, so tokens are reported alongside), cost per merged task, loop incidents, human interventions (steers processed), turns and tokens by role.
6. CLI through `cli/dispatch`: `factory init --repo <path> --goal <name> [--intent <file>]` (repo config if missing, goal directory, intent), `factory run --repo <path> --goal <name> --run <file> [--iterations N]`, `factory status` (derived state, parked causes, last summary path), `factory steer --goal <name> <file | ->` (atomic drop into the inbox). Signals: first SIGINT/SIGTERM drains, second aborts; partial usage is recorded either way. Exit codes distinguish done / blocked / iteration limit / failure.
7. Run configs for the bootstrap, validated by your pre-flight against the real CLIs (harness ids as registered in `src/harness/`; if the opencode and omp adapters are not merged into your branch yet, validate the schema and say so):
   - `bootstrap/run/shakedown.yaml` — every role on zero-cost models through opencode: architect `opencode/minimax-m3.1-flash-free` effort high; pm and digest `opencode/beam-free`; implementer `opencode/deepseek-v4.1-flash-free`; reviewer `opencode/minimax-m3.1-flash-free`; each with fallbacks `opencode-go/deepseek-v4.1-flash` then `alibaba-token-plan/deepseek-v4.1-flash`. Concurrency 3, iterations 1, sessions under `~/.local/share/factory/sessions`, worktrees under `~/.local/share/factory/worktrees`.
   - `bootstrap/run/self.yaml` — same, except architect: harness omp, model `anthropic/claude-opus-5-5`, effort high, scouts pinned to `opencode-go/deepseek-v4.1-flash`; alias `escalation`: omp `anthropic/claude-sonnet-5-5`.
8. Package `README.md`: usage of the four commands, the three config layers with one minimal example each, the goal directory layout, how to steer, what the summary and metrics mean. Short; no design history.
