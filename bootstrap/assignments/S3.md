## Build

1. Prompts: `plugins/software-factory/prompts/` becomes the only home of the role prompts (architect, pm, implementer, reviewer, digest, partials) — content from the drafts, changed only where the code proves a variable wrong. An undefined variable is an error. Rendered prompts are snapshot-tested. Delete `bootstrap/drafts/prompts/` when done. If a prompt needs an input that the task flow (not yours) does not pass yet, name it in the report.
2. Context pack: a size-capped index, never content — status by slug (merged / parked with cause / pending), rounds per task, short hashes, forwarded concerns calibrated `architect` or `owner` (deduplicated by fingerprint with the kept `core/concerns.ts`), infra commands, a shallow code map with paths, pending steers, links to intent / plan / digest.
3. Architect turn, in the stable goal checkout: `turn = first | relaunch | boundary`; resume the stored session when the harness can and the session is usable, else de novo with the pack. Outcome validated → on `decision: continue` and a harness that can compact, compact and store the new session ref before the process exits. `done | blocked` → summary → the launch ends. The session ref is re-derived from the last architect record, never kept only in memory.
4. PM turn + reconcile: the PM writes `tasks/<slug>.md` from the plan. The script checks what is checkable — unique slugs, deps exist, no cycle, `base` names a parked slug, merged/finished tasks untouched (restore them if touched) — and gives the PM one repair turn carrying the findings; a second failure ends the iteration as blocked with a remarkable. A pending task removed from the plan becomes `cancelled` by a record; a changed pending task is simply re-read at dispatch. The PM never edits `plan.md`: detect and reject.
5. Mailbox: writers put a file into `mailbox/inbox` by tmp + rename; the reader ignores files still changing size. Every steer is read at each boundary and goes to the architect; each `steer <id>:` line in the outcome's `forward` becomes a response file in `mailbox/outbox`, and the steer moves to `mailbox/processed`. Idempotent by content hash.
6. Digest: on the first iteration of a launch, when a previous launch exists, the script aggregates cost and turns by role from the records, then one cheap scout turn adds loops, failures and interventions from the transcripts by path → `iterations/<n>/digest.md`.
7. Iteration summary: derived, always written, also when the previous launch crashed before writing it — architect's decision and assumptions, merged / parked by root cause / pending, debt opened and closed, remarkables calibrated `owner`, metrics. One file in `iterations/<n>/` and a copy in `mailbox/outbox`.
