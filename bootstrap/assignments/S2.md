## Build

1. Review rounds: count per flow from config, default 2. `changes` before the last round → a fix round by the implementer. The follow-up mode is flow config: `same-session` (resume; compact first when the harness can), `de-novo`, or `different-model` (another alias). The last round decides: `reject` → park with cause; anything else → merge, the reviewer's concerns recorded as debt.
2. One item budget: non-infra agent turns per slug; exhausted → park (`budget`). `infra` stops never consume the budget or a review round. The harness layer already retries and falls back; the flow adds no retry of its own.
3. No-progress over history: one fingerprint per round (step, status, verdict, resulting tree or findings). A fingerprint seen anywhere earlier in the item's history → park (`no-progress`); that park record is the loop incident. The sequence A, B, A, B must trip.
4. Outcome statuses: `blocked` / `failed` → park with the cause from the summary; `upscope` → park (`upscope`) so the architect re-plans; spike flow → `finished`, never merged, branch kept.
5. Parked continuation: a task with `base: <parked-slug>` branches from that slug's kept branch instead of the integration head.
6. Merge queue, serial: squash-merge the task onto the current integration head in a scratch worktree, run setup + gates there, move the integration ref only when green, then sync the goal checkout. Conflict → one implementer attempt to merge the integration head into its branch, then park (`conflict`). Gates red on the merged result → not merged, one fix round, then park (`gates`). Never rebase. A crash between the ref move and the record must not produce a second merge on relaunch.
7. Dispatch: branch from the integration head at dispatch time; the setup step runs in every fresh worktree before checks; two tasks with overlapping `scope` never run at once; absolute and per-harness concurrency limits from `Limits`.
8. Drain: optional iteration limits (wall time, total turns) → no new dispatch, in-flight items finish within their own budget, the iteration then ends normally.
9. Every script step (commit, checks, merge, park, finish) is a record; `derive` needs nothing else.

## State you start from

- The skeleton parks `blocked` / `upscope` / `reject` inside `derive`, retries `failed` within the item budget, dispatches and merges serially, and parks at once on a conflict or red merged gates. Custom flow step ids still run only implement/review — make the flow definition drive the steps.
- There is no journal file. A loop incident is the park record with cause `no-progress`; metrics are counted from records.
- `TurnResult.attempts` lists every retry/fallback hop the harness made; keep it in the record.
