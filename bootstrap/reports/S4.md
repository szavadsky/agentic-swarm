## Deviations (reversible choices)
- `digest` is not a required pre-flight role: the kernel never calls it, and requiring it would break scenario 1. Every alias present in the run config is still validated.
- Scenario 1's first launch now asserts exit 3 (iteration limit), not 0 — the new exit-code contract distinguishes done/blocked/limit/failure. Behavior is unchanged.
- Metrics are written before the summary in the launch path, but `summary.ts` (forbidden) does not embed them and `backfillSummaries` writes summary first; per-iteration/root/outbox `metrics.yaml` are the source of truth.
- Pre-flight accepts opencode caps variants shaped `{id}` in addition to strings, then writes the resolved effort back into the run config. No harness edit.
- `init` never overwrites an existing intent; re-running with an identical `--intent` is accepted, a different one errors.
- The live test asserts the literal `~/.local/share/factory/...` paths, then redirects roots to temp siblings before probing so operator state is untouched.
- Fallback effort is not separately configurable, so pre-flight validates fallback model/capability only; the turn passes the primary effort to fallbacks (existing agent behavior).
